# Aislamiento del ciclo de captura

El log local acredita un destino central válido y ninguna ventana adicional; se pierde Pointer Capture antes de liberar el botón mediante CDP. Los eventos DOM muestran `lostpointercapture` y movimiento con `buttons: 0` en otra posición, sin `pointerup` solicitado. El origen físico exacto de la pérdida de captura en Electron permanece sin demostrar.

El caso de DOM aislado en Chromium con código productivo reproduce el efecto de un movimiento sin botón tras un destino válido (`dock7-no-button.log`): se limpia la vista previa y no se confirma ni desacopla. La ejecución CDP normal en una pestaña nueva pasa (`dock7-headless.log`). Las pruebas de Chromium visible/X11 con documento aislado devolvieron captura rechazada también con entradas de sistema; no se cuentan como PASS de docking. Las políticas del navegador impiden navegación normal a la fixture. El driver XTEST del nuevo runner se verificó por separado sobre Xvfb (`dock7-x11-qa.log`): pulsación, desplazamiento, liberación, rechazo de doble pulsación y movimiento sin botón, limpieza repetible.
